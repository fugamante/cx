Start Here: Verify What You’re Running

Prefer Rust execution. If a command routes through Bash fallback, expect reduced guarantees and inspect routing before continuing. 

cd <repo-root>
./bin/xshelf version
./bin/xshelf task check --json
./bin/xshelf core --json
./bin/xshelf diag --json --window 20
./bin/xshelf where version diffsum-staged task optimize
Expected: runtime identity, task readiness, backend state, recent diagnostics, and parseable JSON before backend execution is attempted.

Orientation

XSHELF is a runtime substrate, not a chat transcript. It constrains repository output before model use, validates structured results, and records enough evidence to explain a run later.

Canonical runtime

  • rust/cxrs is authoritative runtime behavior.
  • bin/xshelf is the primary entrypoint.
  • bin/xs is the short alias.
  • bin/cx remains a compatibility alias.

Runtime state

  • .cx/schemas/ stores schema contracts.
  • .cx/cxlogs/ stores append-only telemetry.
  • .cx/quarantine/ stores invalid structured output.
  • .cx/ also holds task/runtime metadata.

The Pipeline

The core reliability move is that system output is constrained before it becomes prompt text.

raw system output
  -> internal native reduction
  -> mandatory budgeting (clip/chunk)
  -> embed into prompt
  -> backend execution
  -> schema validation
  -> telemetry append

Budget controls

Variable Purpose
CX_CONTEXT_BUDGET_CHARS Maximum captured character budget.
CX_CONTEXT_BUDGET_LINES Maximum captured line budget.
CX_CONTEXT_CLIP_MODE smart, head, or tail.
CX_CONTEXT_CLIP_FOOTER Controls visible clipping footer evidence. 
./bin/xshelf budget
./bin/xshelf trace

Structured Outputs

Schema commands request JSON-only output, parse JSON, validate it, and quarantine failures. Invalid structured output must be inspectable and replayable. 

./bin/xshelf schema list
./bin/xshelf schema list --json | jq .
./bin/xshelf commitjson | jq .
./bin/xshelf diffsum-staged | jq .
./bin/xshelf next git status | jq .

Failure procedure

./bin/xshelf quarantine list
./bin/xshelf quarantine show <id>
./bin/xshelf replay <id>

Safety Sandbox

The policy engine is the boundary between suggestion and execution.

  • Blocks destructive patterns such as sudo, rm -rf, and shell-piped installers.
  • Blocks privileged ownership/mode changes on system paths.
  • Blocks writes outside the repository root by default.
./bin/xshelf policy show
./bin/xshelf policy show --json | jq .
./bin/xshelf policy check "rm -rf ."

Task Graph

Tasks are the unit of migration to parallel work: small, role-tagged, log-linked, and replayable. 

./bin/xshelf task add "Implement parser hardening" --role implementer
./bin/xshelf task fanout "Ship release notes improvements" --from staged-diff
./bin/xshelf task list --status pending
./bin/xshelf task check --json | jq .
./bin/xshelf task run-all --status pending --events-jsonl --json
./bin/xshelf task events --limit 20 --json
Contract note: --events-jsonl writes additive progress events to stderr and the task event log, while the final stdout JSON remains parseable.

Telemetry

./bin/xshelf logs validate --fix=false
./bin/xshelf telemetry 50 --json | jq .
./bin/xshelf logs stats 200 --json | jq .
./bin/xshelf metrics 50
./bin/xshelf optimize 200 --json | jq .
  • effective_input_tokens high: prompts are too large or too variable.
  • Cache trend down: stabilize prompt templates and capture scope.
  • Clipping frequent: reduce capture scope or raise budgets intentionally.
  • Schema failures spike: enforce deterministic mode and reduce ambiguity.

Backend Selection

./bin/xshelf llm show
./bin/xshelf llm check
./bin/xshelf llm use primary
./bin/xshelf llm use ollama llama3.1
./bin/xshelf llm use llamacpp ggml-org/Qwen3-0.6B-GGUF:Q4_0
./bin/xshelf llm models list --json | jq .
./bin/xshelf llm models inspect local_qwen --json | jq .
./bin/xshelf llm smoke "Respond with OK only."

HTTP transport and local backend claims should stay explicit. Do not infer backend capabilities that are not surfaced through a typed runtime field.
